# 个人主页设计规格

日期：2026-07-07

## 背景与目标

本项目要搭建一个可以被公网访问的个人主页。主页面向招聘方、合作方、朋友和社交访问者，整体定位为“偏专业的公开个人名片”：先建立专业可信度，再通过兴趣和生活片段展示真实、亲近的一面。

第一版目标是快速上线一个稳定、清晰、易维护的静态单页网站，部署到 GitHub Pages，并使用免费的 `用户名.github.io` 地址访问。

## 范围

### 包含

- 单页个人主页
- 首屏介绍
- 关于我
- 技能展示
- 项目作品展示
- 兴趣生活片段
- 联系方式和社交链接
- 响应式布局，适配桌面和手机
- GitHub Pages 部署说明

### 不包含

- 博客或文章系统
- 后台管理
- 评论系统
- 登录系统
- 数据库或后端服务
- 访问统计
- 简历下载
- 自定义域名配置

## 用户与使用场景

主要访问者包括：

- 招聘方或合作方：希望快速了解站点所有者是谁、擅长什么、做过什么项目、如何联系。
- 朋友或社交访问者：希望了解站点所有者的兴趣、性格和生活侧面。

典型访问路径：访客打开主页后，先通过首屏获得第一印象，再浏览项目、技能和兴趣内容，最后通过邮箱、GitHub 或社交链接联系。

## 信息架构

页面采用单页滚动结构，顶部导航使用锚点跳转。内容顺序如下：

1. 首屏介绍
   - 姓名或昵称
   - 职业方向或身份标签
   - 一句话价值描述
   - 头像、照片或首字母图形
   - 主要行动按钮：查看项目、联系我
   - 社交链接
2. 关于我
   - 简短背景介绍
   - 当前关注方向
   - 希望展示的个人特质
3. 技能
   - 按类别或标签展示技术、工具和能力
   - 只展示真实掌握或正在重点使用的内容
4. 项目作品
   - 展示 2 到 4 个代表项目
   - 每个项目包含名称、简介、技术栈、GitHub 链接或在线预览链接
5. 兴趣生活
   - 简短展示兴趣爱好、生活片段或长期关注的主题
   - 作为专业信息的补充，不喧宾夺主
6. 联系方式
   - 邮箱链接
   - GitHub 链接
   - 其他社交平台链接

## 视觉设计

视觉方向采用“简洁专业名片”：

- 浅色背景，保证阅读舒适
- 深色文字，提升专业感和可读性
- 使用适度留白，避免信息拥挤
- 使用一个温和强调色呈现按钮、链接和重点信息
- 项目和技能使用卡片或标签样式组织
- 兴趣生活区域比项目区域更轻量，避免弱化专业定位

整体气质应专业、干净、可信，同时保留个人温度。

## 交互设计

交互保持轻量：

- 顶部导航点击后滚动到对应区块
- 项目卡片提供外链按钮
- 邮箱使用 `mailto:` 链接
- 外部链接在新窗口打开
- 桌面端显示完整导航
- 移动端使用可读的紧凑导航；如空间不足，可使用简单折叠菜单
- 按钮、链接和卡片可以有轻微 hover 效果

核心内容不依赖 JavaScript。即使脚本失效，访客仍能阅读主要信息并使用链接。

## 技术架构

采用纯静态网站结构：

```text
index.html
styles.css
script.js
assets/
README.md
```

职责划分：

- `index.html`：页面结构和文本内容
- `styles.css`：布局、颜色、响应式样式、按钮、卡片和标签样式
- `script.js`：少量增强交互，例如移动端导航或平滑滚动
- `assets/`：头像、图片、项目截图和图标
- `README.md`：本地预览、内容修改和 GitHub Pages 部署说明

## 部署设计

部署目标是 GitHub Pages：

- GitHub 仓库命名为 `GitHub用户名.github.io`
- 将静态文件推送到默认分支
- 启用或使用默认 GitHub Pages 发布规则
- 公网访问地址为 `https://GitHub用户名.github.io`

如果当前本地目录还不是 Git 仓库，实施阶段需要初始化 Git 仓库，再由用户提供或确认 GitHub 用户名与远程仓库地址。

## 测试与验证

完成实现前需要验证：

- 本地浏览器可以正常打开首页
- 桌面宽度下布局清晰、无明显溢出
- 手机宽度下导航、卡片和按钮可用
- 导航锚点可以跳转到正确区块
- 项目链接、邮箱链接、GitHub 链接可点击
- 图片缺失时页面仍可阅读
- GitHub Pages 地址可以公网访问
- 页面中没有 `TODO`、`待定` 或未替换的临时标记

## 内容策略

第一版允许使用稳妥的通用文案，但不能出现明显未完成标记。若用户暂时没有完整资料，页面会使用可公开展示的中性表达，并把具体姓名、项目、技能和链接作为实施前需要确认的内容。

## 成功标准

- 用户拥有一个可公网访问的个人主页
- 页面第一印象偏专业，同时展示少量个人兴趣
- 访客能在 30 秒内理解站点所有者是谁、擅长什么、做过什么、如何联系
- 网站可直接通过 GitHub Pages 部署
- 第一版结构简单，后续可扩展为多页面、博客或自定义域名
